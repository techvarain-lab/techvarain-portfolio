# Variant E — Portfolio (single-file)

Personal GHL Specialist / Funnel Builder portfolio. One self-contained page — no build step, no framework, deploys straight to GitHub Pages.

## Project facts

- **Single file:** `index.html` (~2,300 lines, ~247 KB) — CSS, panels, and JS all inline, plus the inlined PSGCIMBTFLO SVG in `<template id="psmChart">` (~21 KB, one long line). All edits to the site happen here. (The old "~161 KB" was already stale by 55 KB at `2934098`.)
- **Assets:** `assets/` holds images only. `assets/funnel/<slug>/` = `thumb.webp`, `full.webp`, `secNN.webp` per case study; `assets/work/` = automation/funnel screenshots; `assets/ghl/` = GHL proof shots.
- **Deploy:** GitHub Pages from `main`. `.nojekyll` present. No build/verify script — sanity-check by opening `index.html` or the Pages URL.
- **No analytics/hard-coded Netlify forms here** (Rubio funnel has `fbq`/`gtag` hooks; this portfolio itself does not).
- **Resume (not the site):** `resume/index.html` + the generated `resume/rainier-dimasacat-jr-gohighlevel-specialist.pdf`, both tracked, and the PDF is therefore **public** at `/resume/…`. Single page at 0.5in margins; it overflows to 2 if content grows, and the content box to measure against is **7.5in wide, not 8.5in**.
- **`diagrams/` is now FULLY ORPHANED and gitignored (2026-10-01). Nothing in it ships or is referenced.** The chart in the n09 drawer is an **inline copy inside `index.html`** (`<template id="psmChart">`), lifted out of the Archify artifact and re-skinned by hand. `git check-ignore diagrams/…` now matches everything in the directory, including the local `.diagram-design` profile marker.
  - **`psgcimbtflo.architecture.json` remains the upstream source of truth** for the chart's content. Edit the JSON, never the inline copy. Rebuild the artifact with the Archify skill: `validate architecture … --quality showcase` (must be **9/9 checks, 0 errors, 0 warnings**) → `deliver` → `visual-check`. Spec `194bd5f1…`, artifact `b716b22a…`.
  - ⚠️ **The inline copy does NOT regenerate. This is the single biggest trap in the diagram.** There is no build step, so a future `deliver` on the JSON will silently leave the site's chart stale — two copies, no reconciliation. If you re-cut the diagram, you must **re-extract the SVG by hand**: pull `<svg>…</svg>` out of the freshly delivered HTML, flip `data-preset` to `editorial`, delete the baked-in legend (`<g data-legend="" data-legend-bridge="">`, a *balanced* element — do not regex it naively, the two item groups are children), tighten the `viewBox` to `0 0 1150 360` (the last diagram label sits at y=330; the shipped 520 wasted 190 units of dead space below it), and splice it back between `<template id="psmChart">` and `</template>`. Verify by measurement, not by eye: see the assertions under the n09 convention below.
  - **`psgcimbtflo-steps.html`** (the editorial hand-authored variant, `viewBox 0 0 1200 624`) and **`psgcimbtflo.html`** (the 812 KB viewer) are both dead weight and are kept only for local reference. Neither is referenced from the site.
  - **The skin is not hand-invented.** Tokens and families are the `rainier-portfolio` Diagram Design profile (`~/.diagram-design/profiles/rainier-portfolio.md`), selected by the project marker `.diagram-design` (`profile: rainier-portfolio`) in the repo root. It maps the site's own Warm Ink custom properties 1:1, including the inversion where `paper` (page) = `--ground` and `paper-2` (node fill) = `--paper`. **Edit the profile, not the file**, if the site's tokens change. Two rules in it are easy to undo by accident: **`soft` is decoration-only** (~2.8:1 on paper — never readable copy, which uses `muted`), and **neither DM Sans nor Fragment Mono carries Cyrillic**, so a non-Latin diagram needs the font link extended.

Without the wrapper the 64px track won at ≤1024px, `.rail` was `display:none` so nothing filled it, `.main` took the empty 64px track, and the whole site collapsed to 64px wide on every phone (shipped in `6b355e6`, fixed 2026-09-29). `.rail-spine-mark{display:none}` is the base state and must stay *outside* the query.
- **Verify `main` fills the viewport, don't just check for overflow.** A `docOvf === 0` assertion passes trivially when everything is collapsed into a sliver — that blind spot is exactly how the 64px bug survived five suites. At ≤1024px assert `main.clientWidth ≈ innerWidth` and `.rail` is `display:none`; above it assert `main ≈ innerWidth - rail`. Run it across all six panels, not just Work.
- **Spine contents (Work only, 64px column):** `.rail-top` = `RD` mark + `#railPinBtn` (38px amber-filled square, `»`/`«`); bottom-anchored `.rail-spine-mark` = `writing-mode:vertical-rl` + `rotate(180deg)` wordmark, whose rotation also flips its `border-bottom` into the hairline above it. The marketing blocks are killed by `.rail-scroll > *:not(.rail-top):not(.rail-spine-mark)` — that rule needs `!important` because the h1/role wrapper, `.rail-actions` and `.rail-contact` all carry inline `display:` in the markup.
- **Verification effort is tiered by blast radius — do not re-run the whole suite for a small edit.** A copy/tag/class tweak costs a syntax check and a look at the diff. A single component's layout costs that plus one measurement *of that component only*. A full sweep (all tiles, both viewports, screenshots) is reserved for shared CSS, the renderer, or anything with a documented failure mode — the `.cs-case`/`.ghl-split` column-top check, the rail's `main`-fills-viewport check, and the drawer/`display:contents` mobile order. That distinction is not laziness: those three have shipped broken in this repo's history, and each was invisible to a plain screenshot (a lazily-decoded canvas, a 64px collapse, an 823px scroll floor). **Do not re-verify a previous, unrelated change after an edit elsewhere** — it cannot detect a regression there and burns the budget the next real task needs.
- **Editing trap: this repo is UTF-8 with LF in git and `core.autocrlf=true`.** Any tool that rewrites a file's bytes wholesale — `[System.IO.File]::ReadAllText`/`WriteAllText` round-trips, `Out-File`, etc. — can silently mojibake every non-ASCII character (an em dash becomes the three-byte sequence `a-circumflex euro`), flip line endings, and inflate a 10-line diff to 200. Prefer the edit tool, or `Add-Content -Encoding UTF8` for appends. **Read the diff back after any write you did with shell commands**, and check `git diff --numstat` for an implausible count.
- **Rail vertical rhythm:** `.rail-scroll` is `space-between`, so **removing or adding a child redistributes every gap in the rail** (~24px per gap at a 900px viewport when one 48px block is removed). The rail's scrollbar is hidden, so an over-tall rail overflows *silently* — always measure `scrollHeight - clientHeight` at ~720px viewport height after changing rail content, and spend freed space deliberately (`:952` `margin-top:34px` on `.rail-actions`, plus `.rail-copy` leading) rather than letting it become evenly-sized voids.
- **One theme control, never two:** the rail's `#themeBtn` is hidden *only* while collapsed, and the topbar's `#themeTopBtn` (beside `▦ BG`, desktop-gated at `min-width:1025px`) is shown *only* while collapsed. Both are bound to a shared `toggleTheme()`. If you add a third entry point, keep the mutual exclusion or you will ship duplicates.
- **Headless-verify caveat:** headless Edge runs the page at `visibilityState: "hidden"`, which **freezes** CSS transitions (a `CSSTransition` sits at `state=running, currentTime=0`), so any post-change measurement reads the stale start value — finish animations (`el.getAnimations().forEach(a=>a.finish())`) before measuring geometry. The same applies to `?t=` navigation (a hash-only `Page.navigate` is a same-document no-op, so give each load a unique query string) and to `getComputedStyle` on a child of a `display:none` parent (it still reports the child's own `display`, so use `checkVisibility()`). Confirm rules with `CSS.getMatchedStylesForNode` rather than inferring from computed values. Also: `document.styleSheets[0].cssRules` is SecurityError-blocked on `file://` (check dead CSS in the shell), and `.spec-icon` is a **shared** class also used by the GHL tiles (a document-wide count returns 13, not 5 — scope it). **Screenshots over CDP need two specific things in this Edge build:** `Page.captureScreenshot` with `fromSurface:false` returns **blank frames**, so leave the default; and it **hangs indefinitely** while any transition or animation is live (reproducible on `#drawer` and on `scrollIntoView`). Inject a killswitch before capturing — `*,*::before,*::after{transition:none !important;animation:none !important}` — which settles the compositor. Related trap: `/json/list` on the debug port returns **every** tab in the profile, and `list.find(t => t.type==='page')` will happily hand you an unrelated tab (it returned a Grammarly signup page, whose `projects is not defined` looked like a site bug). Always match the target by URL, e.g. `/index\.html/.test(t.url)`. `--dump-dom` and `--headless=old` are both no-ops in this build; CDP on `--remote-debugging-port` is the only reliable path, and a URL containing spaces must be percent-encoded or the page never loads.
- **Tab strip is tight below 1280px.** `#ptabs` is 6 tabs; renaming `WORK` to `PORTFOLIO BUILDS` (2026-09-29) grew that tab 92px → 180px and `ABOUT` to `ABOUT ME` added 67px → 89px. At ≥1280px the topbar absorbs it (all tabs visible), but **1025–1279px now overflows the strip** and 2–3 tabs sit behind the `updTabs()` `.ov` edge-fade needing a horizontal scroll — accepted, and the mask is the affordance. Never widen a `.ptab` label without re-measuring `scrollWidth` vs `clientWidth` at 1100px, not just 1440px.
- **Images:** add sections as `sec01..secNN.webp` under `assets/funnel/<slug>/`; never hotlink. GHL proof under `assets/ghl/proof-*.png`. Automation workflow canvases go under `assets/work/` as **PNG** (there is no `.webp` precedent in `assets/work/`, only in `assets/funnel/`).
- **`prev-crop` is a measurement, not a preference.** `:1367` (multi-image) and `:1371` (single/`p.img`) each carry a hardcoded `n` allowlist, currently `['22','07','08','25']`. The rule: **tall canvases → `prev-crop` (16:9 cover), wide/16:9 → `prev-full`/`prev-hero` at natural size.** Every crop-listed id is a tall GHL canvas (n07 0.557, n08 0.763, n22 0.43, n25 0.34–0.82) and every `prev-full` id is already ~16:9 (n09 1.76, n10 1.77) or a funnel page. **When adding a build, measure the screenshot's aspect ratio and add the `n` to both lists only if it is tall** — do not add it by habit. The cost is real and accepted: a 16:9 cover shows just `ar/1.777` of the height, so n25 flow 2 (0.343) reveals the top ~19% in the bench while flow 1 (0.823) shows ~46%; rows stay a uniform height and the lightbox carries the full canvas. Related: `p.img` is the **card/preview** thumbnail, so pick the project's *widest* canvas for it, not its most important one — n25 uses `legal-capture.png` (0.823) for exactly this reason. **n26 was measured and deliberately NOT added, despite being the tallest funnel page yet** (ar 0.192): every existing funnel renders a tall `full.webp` through `prev-full` inside a scrolling `.preview-body`, so 0.192 sits in the same family as clearview 0.23 / haven 0.242 / rubio 0.313, not a new class.
- **Funnel asset conventions, measured from the six existing folders (2026-10-02).** All are `.webp` at **29–44 KB/megapixel** — never ship PNGs. `full.webp` = the **entire tall page** (existing ars 0.23–0.47). `secNN.webp` are slices at **ar 1.1–2.4** (800–1700px tall) which, historically, **exactly partition `full.webp`** — ClearView's five slices sum to 8,353px = its `full` height, Legal 5×826 = 4,130 exact, FitCoach 6×~965 = 5,792 exact. `thumb.webp` is one of two patterns: a 640px-wide scaled copy of `full` (rubio, fitcoach, legal) or an 800px-wide **top crop** at ar ~1.6 (clearview, haven, mountain-hiking). **n26 is the first build to break the partition invariant**: its 8 sections are 6 slices of the landing (1,668px each — 10,008 ÷ 6, no remainder) plus the booking and thank-you pages as whole sections, because it is a **3-page funnel** and all three pages belong in the case study. Nothing enforces the invariant; the drawer just stacks `sections[]`. Encode by **calibrating quality to hit the KB/MPix band** rather than picking a fixed quality blind. Note the drawer appends `p.full` as a **9th** image below the stack, so assert `sections.length + 1` bright-minds images, not `sections.length`.

## Working agreements (token efficiency)

Do NOT re-read all of `index.html` to "catch up". Orienting to recent work is cheap:

1. Start of session: run `/catchup` (git log oneline + `git diff --stat` + CHANGELOG tail).
2. Target reads — use `grep` or `Read` with a line window from the File map above, not the whole file.
3. For "what changed since last week," use `git log` / `git diff`; commit messages carry the summary.
4. Long project entries (Rubio/ClearView/Haven/Legal) have single-line JSON — `Read` truncates at 2000 chars; use `Read` with `offset` at the entry, or `grep` for the field you need.
5. After finishing work, run `/wrapup` to append today's entry to `CHANGELOG.md` (or the user will run it). Keep each entry to a few bullet lines.
