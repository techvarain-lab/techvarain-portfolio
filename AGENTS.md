# Variant E — Portfolio (single-file)

Personal GHL Specialist / Funnel Builder portfolio. One self-contained page — no build step, no framework, deploys straight to GitHub Pages.

## Project facts

- **Single file:** `index.html` (~1,640 lines, ~161 KB) — CSS, panels, and JS all inline. All edits to the site happen here.
- **Assets:** `assets/` holds images only. `assets/funnel/<slug>/` = `thumb.webp`, `full.webp`, `secNN.webp` per case study; `assets/work/` = automation/funnel screenshots; `assets/ghl/` = GHL proof shots.
- **Deploy:** GitHub Pages from `main`. `.nojekyll` present. No build/verify script — sanity-check by opening `index.html` or the Pages URL.
- **No analytics/hard-coded Netlify forms here** (Rubio funnel has `fbq`/`gtag` hooks; this portfolio itself does not).

## Conventions

- **Aesthetic:** editorial-mono. Fonts: Instrument Serif (display) + Fragment Mono (labels) + Cormorant Garamond accents. Ink on paper, amber accent, hairline `var(--line)` borders.
- **BG tweak:** topbar "▦ BG" button tests background treatments live (`.main[data-bg=*]` switcher, persists `rd-bg` in localStorage, mirrors theme pattern). Default `grid`. Mode list in `#bgPop`; keep `.bg-opt` rows in sync with `BG_OPTS` + `data-bgopt` + mode CSS + swatch classes.
- **Tags/taxonomy:** `funnel` / `automation` only — the Hybrid category was removed 2026-09-22 (old hybrids 01 Rubio → funnel, 04 Haven → automation, 05 FitCoach → automation, 06 Legal → funnel). **Both chips count BUILDS** (Funnel 6 / Automation 11, reconciling to 17) — the `All 17` chip was removed 2026-09-29 and `Automation` no longer shows 29, because the old row mixed units (17 and 6 builds vs 29 automations), which is why that chip needed a tooltip to explain itself. **29 automations is still the headline automation number**, surfaced in the chip's `title="11 builds · 29 automations"`, the `#workSearch` placeholder "Search 29 automations…", and each group's `N workflows` pill. Keep the `family`/`tags`/`flows[]` fields in sync with the chip: 11 automation builds carry `flows[]` totalling 29 (n04:3 n22:3 n05:3 n07:4 n08:4 n09:5 n10:3 n12:1 n13:1 n14:1 n16:1), and 6 funnel builds have none.
- **Work opens on Automation.** `curFilter='automation'` (`:1237`) and the `Automation` chip ships with `class="active"`, so the grouped card view (11 build groups + 29 flow rows) is the landing view. **Do not restore the bare `setPreview(active)` at the end of the init line** — `render()`'s automation branch already selects the first *flow* and sets `activeId="04.1"`; calling `setPreview(active)` again clobbers that flow-level selection (and `setPreview` reassigns `active`, so the second call no longer even receives the flow). The init is `render(); if(activeId===null) setPreview(active);`.
- **Hero carousel** shows the 6 featured builds via `heroProjectNs` at line 1477 — currently `["01","08","22","04","05","06"]`, a deliberate **2 funnel / 4 automation** mix (was `01,02,03,04,05,06` = 5 funnel / 1 automation). Dropped **02 Mountain Hiking** and **03 ClearView**; added **08 FlowFix Plumbing** (`assets/work/flowfix-intake.png`, fallback `flowfix-triage.png`) and **22 TorqueWorks Dormant Win-Back** (`assets/work/torqueworks-1.png`, fallback `torqueworks-3.png`) — both were chosen because they are the only automation builds with real carousel-worthy media. **09 was rejected**: 5 flows but no `sections[]`/flow media at all. The 6 slots, the 6 `#heroLiveDots` buttons and the `%6` modulus in `startHeroLive` are all still 6, so the carousel machinery is unchanged. The track `<img>` list (`:1025`) and the 6 `#heroSideList` items (`:1045`) are **hardcoded** and must be edited in step with `heroProjectNs` — the `heroLiveTitles/Descs/Stacks` arrays do derive from it, but the side items do not. A side item's `Live` tag must only appear when that project actually has a `liveUrl` (01, 04, 06 have one; 05, 08, 22 do not), matching the `#heroLiveBadge` rule at `:1495`.
- **Hero list height:** the featured list is a `scroll` container with a **hidden scrollbar**, so items that fall below the fold vanish silently. A roomy item measures **139px**; at a 900px viewport the list has 721px for 6 items + gaps, so only 4/6 fit. Fixed with a **height**-gated compaction at `:742` — `@media (max-height:940px) and (min-width:1061px)` tightens padding 12→9px, gap 6→7px→4px, title 14.5→13.5px, desc 12.5→12px, small 9→8.5px, **keeping 2-line descriptions**. That yields **5/6 visible at 900px, 6/6 at 1080px+**, and 1080px+ is pixel-identical to the uncompacted design because the gate is on `height`, not width. Verify with `itemH` (116px compacted / 139px roomy), `list.clientHeight+'/'+scrollHeight`, and a count of items whose `bottom <= list.bottom`. **Measure at more than one viewport height** — this is the same class of trap as the rail's silent overflow.
- **Counts to keep current:** nav tab "PORTFOLIO BUILDS **17**" (renamed from "WORK — 17" 2026-09-29; the `17` rides in `.cnt`), toolbar chips (**Funnel 6 / Automation 11** — both in builds), `heroProjectNs` length (6, at line 1477), CONTACT reads "24h reply". Nav labels are `HOME · WHAT I DO IN GHL · PORTFOLIO BUILDS · SERVICES · ABOUT ME · CONTACT` (ABOUT renamed from "ABOUT" the same day) — keep the topbar (`:975-980`) and the mobile drawer (`:1197-1202`) in sync; the internal `data-panel` ids were deliberately left as `work`/`about` because `switchPanel`, the hash routes and `heroProjectNs` key off them. **The hero ghost is now count-free** (`See the automations →`, `:1079`) and the work tab's `data-hint` dropped its "17 builds" — so as of 2026-09-29 there are **no count-bearing CTAs left to go stale**, which retires a trap this repo has already fallen into twice. **Conversion CTAs all read "Hire me →"** (6 sites: rail `:953`, topbar `:984`, hero `:1061`, mobile rail `:1178`, mobile nav `:1197`); keep them in sync, and note the hero's amber primary is the *convert* action with "See the automations" demoted to the ghost. GHL tiles = `glSkills` length (9: 01–08 graduated/copy-backed skills, 09 `featured` PSGCIMBTFLO banner). n09 subs = 11 steps; the banner remains, but no embedded workflow chart or roomy drawer behavior remains.
- **Rail collapse:** the left rail is a full 320px on every panel **except Work**, where it narrows to a 64px spine and frees 256px for the workbench. Scoped to Work deliberately — a first pass collapsed every non-Home panel and read as messy (GHL went to 6-across with tighter truncation). State is two attributes on `<html>`: `data-view` (active panel, written by both the head bootstrap and `switchPanel`) and `data-rail` (`auto` | `pinned`, persisted in `rd-rail`; `pinned` = hold the full rail even on Work). Collapse CSS keys off `[data-rail="auto"][data-view="work"]` **inside `@media(min-width:1025px)`**, so adding a panel means widening that condition and the `.rail-pin` `:not()` rule. **Do not unwrap that media query** — the collapse selectors are (0,3,0) and the mobile block's `.app{grid-template-columns:1fr}` is only (0,1,0), and specificity is compared *before* source order. Without the wrapper the 64px track won at ≤1024px, `.rail` was `display:none` so nothing filled it, `.main` took the empty 64px track, and the whole site collapsed to 64px wide on every phone (shipped in `6b355e6`, fixed 2026-09-29). `.rail-spine-mark{display:none}` is the base state and must stay *outside* the query.
- **Verify `main` fills the viewport, don't just check for overflow.** A `docOvf === 0` assertion passes trivially when everything is collapsed into a sliver — that blind spot is exactly how the 64px bug survived five suites. At ≤1024px assert `main.clientWidth ≈ innerWidth` and `.rail` is `display:none`; above it assert `main ≈ innerWidth - rail`. Run it across all six panels, not just Work.
- **Spine contents (Work only, 64px column):** `.rail-top` = `RD` mark + `#railPinBtn` (38px amber-filled square, `»`/`«`); bottom-anchored `.rail-spine-mark` = `writing-mode:vertical-rl` + `rotate(180deg)` wordmark, whose rotation also flips its `border-bottom` into the hairline above it. The marketing blocks are killed by `.rail-scroll > *:not(.rail-top):not(.rail-spine-mark)` — that rule needs `!important` because the h1/role wrapper, `.rail-actions` and `.rail-contact` all carry inline `display:` in the markup.
- **Rail vertical rhythm:** `.rail-scroll` is `space-between`, so **removing or adding a child redistributes every gap in the rail** (~24px per gap at a 900px viewport when one 48px block is removed). The rail's scrollbar is hidden, so an over-tall rail overflows *silently* — always measure `scrollHeight - clientHeight` at ~720px viewport height after changing rail content, and spend freed space deliberately (`:952` `margin-top:34px` on `.rail-actions`, plus `.rail-copy` leading) rather than letting it become evenly-sized voids.
- **One theme control, never two:** the rail's `#themeBtn` is hidden *only* while collapsed, and the topbar's `#themeTopBtn` (beside `▦ BG`, desktop-gated at `min-width:1025px`) is shown *only* while collapsed. Both are bound to a shared `toggleTheme()`. If you add a third entry point, keep the mutual exclusion or you will ship duplicates.
- **Headless-verify caveat:** headless Edge runs the page at `visibilityState: "hidden"`, which **freezes** CSS transitions (a `CSSTransition` sits at `state=running, currentTime=0`), so any post-change measurement reads the stale start value — finish animations (`el.getAnimations().forEach(a=>a.finish())`) before measuring geometry. The same applies to `?t=` navigation (a hash-only `Page.navigate` is a same-document no-op, so give each load a unique query string) and to `getComputedStyle` on a child of a `display:none` parent (it still reports the child's own `display`, so use `checkVisibility()`). Confirm rules with `CSS.getMatchedStylesForNode` rather than inferring from computed values. Also: `document.styleSheets[0].cssRules` is SecurityError-blocked on `file://` (check dead CSS in the shell), and `.spec-icon` is a **shared** class also used by the GHL tiles (a document-wide count returns 13, not 5 — scope it).
- **Tab strip is tight below 1280px.** `#ptabs` is 6 tabs; renaming `WORK` to `PORTFOLIO BUILDS` (2026-09-29) grew that tab 92px → 180px and `ABOUT` to `ABOUT ME` added 67px → 89px. At ≥1280px the topbar absorbs it (all tabs visible), but **1025–1279px now overflows the strip** and 2–3 tabs sit behind the `updTabs()` `.ov` edge-fade needing a horizontal scroll — accepted, and the mask is the affordance. Never widen a `.ptab` label without re-measuring `scrollWidth` vs `clientWidth` at 1100px, not just 1440px.
- **Images:** add sections as `sec01..secNN.webp` under `assets/funnel/<slug>/`; never hotlink. GHL proof under `assets/ghl/proof-*.png`.

## Working agreements (token efficiency)

Do NOT re-read all of `index.html` to "catch up". Orienting to recent work is cheap:

1. Start of session: run `/catchup` (git log oneline + `git diff --stat` + CHANGELOG tail).
2. Target reads — use `grep` or `Read` with a line window from the File map above, not the whole file.
3. For "what changed since last week," use `git log` / `git diff`; commit messages carry the summary.
4. Long project entries (Rubio/ClearView/Haven/Legal) have single-line JSON — `Read` truncates at 2000 chars; use `Read` with `offset` at the entry, or `grep` for the field you need.
5. After finishing work, run `/wrapup` to append today's entry to `CHANGELOG.md` (or the user will run it). Keep each entry to a few bullet lines.
