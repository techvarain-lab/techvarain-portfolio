# Variant E — Portfolio (single-file)

Personal GHL Specialist / Funnel Builder portfolio. One self-contained page — no build step, no framework, deploys straight to GitHub Pages.

## Project facts

- **Single file:** `index.html` (~1,640 lines, ~161 KB) — CSS, panels, and JS all inline. All edits to the site happen here.
- **Assets:** `assets/` holds images only. `assets/funnel/<slug>/` = `thumb.webp`, `full.webp`, `secNN.webp` per case study; `assets/work/` = automation/funnel screenshots; `assets/ghl/` = GHL proof shots.
- **Deploy:** GitHub Pages from `main`. `.nojekyll` present. No build/verify script — sanity-check by opening `index.html` or the Pages URL.
- **No analytics/hard-coded Netlify forms here** (Rubio funnel has `fbq`/`gtag` hooks; this portfolio itself does not).
- **Resume (not the site):** `resume/index.html` + the generated `resume/rainier-dimasacat-jr-gohighlevel-specialist.pdf`, both tracked, and the PDF is therefore **public** at `/resume/…`. Rebuild by re-rendering the HTML with headless Edge (`--print-to-pdf-no-header`); there is no pandoc/wkhtmltopdf/libreoffice on this machine. `resume-print-preview.png` is gitignored, like `/prototypes/`. **The PDF hardcodes counts that go stale** — 18 builds, 12 automation systems, 38 workflows, 6 funnels, 4 roles, 9 GHL skills — so regenerate it whenever `projects` or `glSkills` changes, the same trap this repo has already fallen into twice with count-bearing CTAs. Single page at 0.5in margins; it overflows to 2 if content grows, and the content box to measure against is **7.5in wide, not 8.5in**.

## Conventions

- **Aesthetic:** editorial-mono. Fonts: Instrument Serif (display) + Fragment Mono (labels) + Cormorant Garamond accents. Ink on paper, amber accent, hairline `var(--line)` borders.
- **BG tweak:** topbar "▦ BG" button tests background treatments live (`.main[data-bg=*]` switcher, persists `rd-bg` in localStorage, mirrors theme pattern). Default `grid`. Mode list in `#bgPop`; keep `.bg-opt` rows in sync with `BG_OPTS` + `data-bgopt` + mode CSS + swatch classes.
- **Tags/taxonomy:** `funnel` / `automation` only — the Hybrid category was removed 2026-09-22 (old hybrids 01 Rubio → funnel, 04 Haven → automation, 05 FitCoach → automation, 06 Legal → funnel). **Both chips count BUILDS** (Funnel 6 / Automation 12, reconciling to 18) — the `All 17` chip was removed 2026-09-29 and `Automation` no longer shows 38, because the old row mixed units (18 and 6 builds vs 38 automations), which is why that chip needed a tooltip to explain itself. **38 automations is still the headline automation number**, surfaced in the chip's `title="12 builds · 38 automations"`, the `#workSearch` placeholder "Search 38 automations…", and each group's `N workflows` pill. Keep the `family`/`tags`/`flows[]` fields in sync with the chip: 12 automation builds carry `flows[]` totalling 38 (n04:3 n22:3 n05:3 n25:9 n07:4 n08:4 n09:5 n10:3 n12:1 n13:1 n14:1 n16:1), and 6 funnel builds have none.
- **Work opens on Automation.** `curFilter='automation'` (`:1237`) and the `Automation` chip ships with `class="active"`, so the grouped card view (11 build groups + 29 flow rows) is the landing view. **Do not restore the bare `setPreview(active)` at the end of the init line** — `render()`'s automation branch already selects the first *flow* and sets `activeId="04.1"`; calling `setPreview(active)` again clobbers that flow-level selection (and `setPreview` reassigns `active`, so the second call no longer even receives the flow). The init is `render(); if(activeId===null) setPreview(active);`.
- **Hero carousel** shows the 6 featured builds via `heroProjectNs` at line 1477 — currently `["01","08","22","04","05","06"]`, a deliberate **2 funnel / 4 automation** mix (was `01,02,03,04,05,06` = 5 funnel / 1 automation). The 6 slots, the 6 `#heroLiveDots` buttons and the `%6` modulus in `startHeroLive` are all still 6, so the carousel machinery is unchanged. The track `<img>` list (`:1025`) and the 6 `#heroSideList` items (`:1045`) are **hardcoded** and must be edited in step with `heroProjectNs` — the `heroLiveTitles/Descs/Stacks` arrays do derive from it, but the side items do not. A side item's `Live` tag must only appear when that project actually has a `liveUrl` (01, 04, 06 have one; 05, 08, 22 do not), matching the `#heroLiveBadge` rule at `:1495`.
- **Hero list height:** the featured list is a `scroll` container with a **hidden scrollbar**, so items that fall below the fold vanish silently. A roomy item measures **139px**; at a 900px viewport the list has 721px for 6 items + gaps, so only 4/6 fit. Fixed with a **height**-gated compaction at `:742` — `@media (max-height:940px) and (min-width:1061px)` tightens padding 12→9px, gap 6→7px→4px, title 14.5→13.5px, desc 12.5→12px, small 9→8.5px, **keeping 2-line descriptions**. That yields **5/6 visible at 900px, 6/6 at 1080px+**, and 1080px+ is pixel-identical to the uncompacted design because the gate is on `height`, not width. Verify with `itemH` (116px compacted / 139px roomy), `list.clientHeight+'/'+scrollHeight`, and a count of items whose `bottom <= list.bottom`. **Measure at more than one viewport height** — this is the same class of trap as the rail's silent overflow.
- **The Legal system is two entries on purpose.** n06 (funnel) and n25 (automation) are halves of **one** client system, split 2026-09-30 so the automation majority is honest — n06 keeps the landing/intake/calendar build and its 9-workflow prose, n25 owns the 9 workflows as individually browsable flows. - **Case-study modal, not a side panel.** `#drawer` was a `width:min(720px,100%)` right-hand sheet; it is now a centred **gutter card** — `min(1280px, 100vw-40px)` x `min(920px, 100vh-40px)`, `border-radius:14px`, opened on `opacity`+`scale`. **Keep the gutter:** `overlay.addEventListener('click', closeDrawer)` is the outside-click-to-close affordance, and a full-bleed drawer would cover the scrim and kill it, leaving only the ✕ and Escape. `.drawer` is `overflow:hidden` (its old `overflow:auto` plus `.drawer-body`'s made two scrollers) and that same `overflow:hidden` clips `.drawer-head` to the new corners for free. At `max-width:1024px` the existing block makes it full-bleed again, no gutter. `.drawer{transition:none}` sits in the `prefers-reduced-motion` block.
- **The two columns are flex, not grid — and that is not cosmetic.** The first attempt used `display:grid` with the proof in `grid-column:2` and the text in column 1, which meant both columns **shared a row** and the row's height became `max(text, proof)`. The moment a lazily-decoded canvas went from 0px to 678px, the entire left column was pushed **from `y=190` to `y=885`** and landed below the modal's bottom edge. It measured correct in every screenshot taken *before* decode and broken in every one taken *after*, and `getComputedStyle` plus `elementFromPoint` both reported the text visible and on top — so **assert the two columns' `top` values are equal** rather than trusting paint or hit-testing. The fix is `.cs-case{display:flex}` with real `.cs-colA`/`.cs-colB` wrappers so each column is sized only by its own content, with `.cs-colB{position:sticky}`. `min-width:0` on both, or the wide canvases blow out the flex basis.
- **Mobile order is preserved with `display:contents` + `order`, not by reordering the DOM.** Below 1025px `.cs-colA`/`.cs-colB` are `display:contents` (their grandchildren become flex items of `.cs-case`) and `.cs-proof{order:1}`, `.cs-depth{order:2}`, `.cs-cta{order:3}` put the proof back between the desc and the PROBLEM/SOLUTION/OUTCOME. Verified at 390px: `chips → desc → proof → depth → cta`. Anything new added to `.cs-case` needs an `order` or it lands in DOM position on mobile.
- **The flow-chip strip spans the full modal width** (`.cs-chips{flex:0 0 100%}`), deliberately: the text column is only ~568px — *narrower* than the old 720px panel — so chips confined to it wrapped 9 labels over **5-6 rows**, while full width they fit in **2 rows** at 1280+.

That was true for **13 of 38 flows**: n04, n22, n10, n12, n13, n14, n16. **n04's 3 and n22's 3 were written by hand on 2026-09-30** to close the mismatch. The remaining **7 — n10.1-3, n12.1, n13.1, n14.1, n16.1 — still fall back to nothing**, so those drawers show title + desc and no depth read. When adding flows, give each one its own `problem`/`solution`/`outcome`, or the header will contradict the body.
