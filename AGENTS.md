# Variant E — Portfolio (single-file)

Personal GHL Specialist / Funnel Builder portfolio. One self-contained page — no build step, no framework, deploys straight to GitHub Pages.

## Project facts

- **Single file:** `index.html` (~2,570 lines, ~277 KB) — CSS, panels, and JS all inline, plus the inlined PSGCIMBTFLO SVG in `<template id="psmChart">` (~21 KB, one long line). All edits to the site happen here.
- **Assets:** `assets/` holds images only. `assets/funnel/<slug>/` = `thumb.webp`, `full.webp`, `secNN.webp` per case study; `assets/work/` = automation/funnel screenshots; `assets/ghl/` = GHL proof shots.
- **Deploy:** GitHub Pages from `main`. `.nojekyll` present. No build/verify script — sanity-check by opening `index.html` or the Pages URL.
- **No analytics/hard-coded Netlify forms here** (Rubio funnel has `fbq`/`gtag` hooks; this portfolio itself does not).
- **Resume (not the site):** `resume/index.html` + the generated `resume/rainier-dimasacat-jr-gohighlevel-specialist.pdf`, both tracked, and the PDF is therefore **public** at `/resume/…`. Rebuild by re-rendering the HTML with headless Edge (`--print-to-pdf-no-header`); there is no pandoc/wkhtmltopdf/libreoffice on this machine. `resume-print-preview.png` is gitignored, like `/prototypes/`. **The PDF hardcodes counts that go stale** — it was found **two builds behind** on 2026-10-06 (it still said *18 builds / 6 funnels* while the site was at 19/7, so this trap has now fired four times) — **20 builds (20 as of 2026-10-06, was 19)**, 12 automation systems, 38 workflows, **8 funnels (was 7)**, 4 roles, 9 GHL skills — so regenerate it whenever `projects` or `glSkills` changes, the same trap this repo has already fallen into twice with count-bearing CTAs. It carries the count in **three** places: the summary paragraph, the "Delivered N funnels" bullet, and a "Built N client projects" bullet — grep for all three, not just the first. Single page at 0.5in margins (MediaBox 612×792); it overflows to 2 if content grows, and the content box to measure against is **7.5in wide, not 8.5in**.
- **`diagrams/` is now FULLY ORPHANED and gitignored (2026-10-01). Nothing in it ships or is referenced.** The chart in the n09 drawer is an **inline copy inside `index.html`** (`<template id="psmChart">`), lifted out of the Archify artifact and re-skinned by hand. `git check-ignore diagrams/…` now matches everything in the directory, including the local `.diagram-design` profile marker.
  - **`psgcimbtflo.architecture.json` remains the upstream source of truth** for the chart's content. Edit the JSON, never the inline copy. Rebuild the artifact with the Archify skill: `validate architecture … --quality showcase` (must be **9/9 checks, 0 errors, 0 warnings**) → `deliver` → `visual-check`. Spec `194bd5f1…`, artifact `b716b22a…`.
  - ⚠️ **The inline copy does NOT regenerate. This is the single biggest trap in the diagram.** There is no build step, so a future `deliver` on the JSON will silently leave the site's chart stale — two copies, no reconciliation. If you re-cut the diagram, you must **re-extract the SVG by hand**: pull `<svg>…</svg>` out of the freshly delivered HTML, flip `data-preset` to `editorial`, delete the baked-in legend (`<g data-legend="" data-legend-bridge="">`, a *balanced* element — do not regex it naively, the two item groups are children), tighten the `viewBox` to `0 0 1150 360` (the last diagram label sits at y=330; the shipped 520 wasted 190 units of dead space below it), and splice it back between `<template id="psmChart">` and `</template>`. Verify by measurement, not by eye: see the assertions under the n09 convention below.
  - **`psgcimbtflo-steps.html`** (the editorial hand-authored variant, `viewBox 0 0 1200 624`) and **`psgcimbtflo.html`** (the 812 KB viewer) are both dead weight and are kept only for local reference. Neither is referenced from the site.
  - **The skin is not hand-invented.** Tokens and families are the `rainier-portfolio` Diagram Design profile (`~/.diagram-design/profiles/rainier-portfolio.md`), selected by the project marker `.diagram-design` (`profile: rainier-portfolio`) in the repo root. It maps the site's own Warm Ink custom properties 1:1, including the inversion where `paper` (page) = `--ground` and `paper-2` (node fill) = `--paper`. **Edit the profile, not the file**, if the site's tokens change. Two rules in it are easy to undo by accident: **`soft` is decoration-only** (~2.8:1 on paper — never readable copy, which uses `muted`), and **neither DM Sans nor Fragment Mono carries Cyrillic**, so a non-Latin diagram needs the font link extended.

Also: `document.styleSheets[0].cssRules` is SecurityError-blocked on `file://` (check dead CSS in the shell), and `.spec-icon` is a **shared** class also used by the GHL tiles (a document-wide count returns 13, not 5 — scope it). **Screenshots over CDP need two specific things in this Edge build:** `Page.captureScreenshot` with `fromSurface:false` returns **blank frames**, so leave the default; and it **hangs indefinitely** while any transition or animation is live (reproducible on `#drawer` and on `scrollIntoView`). Inject a killswitch before capturing — `*,*::before,*::after{transition:none !important;animation:none !important}` — which settles the compositor. Related trap: `/json/list` on the debug port returns **every** tab in the profile, and `list.find(t => t.type==='page')` will happily hand you an unrelated tab (it returned a Grammarly signup page, whose `projects is not defined` looked like a site bug). Always match the target by URL, e.g. `/index\.html/.test(t.url)`. `--dump-dom` and `--headless=old` are both no-ops in this build; CDP on `--remote-debugging-port` is the only reliable path, and a URL containing spaces must be percent-encoded or the page never loads.
- **Tab strip is tight below 1280px.** `#ptabs` is 6 tabs; renaming `WORK` to `PORTFOLIO BUILDS` (2026-09-29) grew that tab 92px → 180px and `ABOUT` to `ABOUT ME` added 67px → 89px. At ≥1280px the topbar absorbs it (all tabs visible), but **1025–1279px now overflows the strip** and 2–3 tabs sit behind the `updTabs()` `.ov` edge-fade needing a horizontal scroll — accepted, and the mask is the affordance. - **Funnel asset conventions, measured from the six existing folders (2026-10-02).** All are `.webp` at **29–44 KB/megapixel** — never ship PNGs. `full.webp` = the **entire tall page** (existing ars 0.23–0.47). `secNN.webp` are slices at **ar 1.1–2.4** (800–1700px tall) which, historically, **exactly partition `full.webp`** — ClearView's five slices sum to 8,353px = its `full` height, Legal 5×826 = 4,130 exact, FitCoach 6×~965 = 5,792 exact. `thumb.webp` is one of two patterns: a 640px-wide scaled copy of `full` (rubio, fitcoach, legal) or an 800px-wide **top crop** at ar ~1.6 (clearview, haven, mountain-hiking). **n26 is the first build to break the partition invariant**: its 8 sections are 6 slices of the landing (1,668px each — 10,008 ÷ 6, no remainder) plus the booking and thank-you pages as whole sections, because it is a **3-page funnel** and all three pages belong in the case study. ## Working agreements (token efficiency)

Do NOT re-read all of `index.html` to "catch up". Orienting to recent work is cheap:

1. Start of session: run `/catchup` (git log oneline + `git diff --stat` + CHANGELOG tail).
2. Target reads — use `grep` or `Read` with a line window from the File map above, not the whole file.
3. For "what changed since last week," use `git log` / `git diff`; commit messages carry the summary.
4. Long project entries (Rubio/ClearView/Haven/Legal) have single-line JSON — `Read` truncates at 2000 chars; use `Read` with `offset` at the entry, or `grep` for the field you need.
5. After finishing work, run `/wrapup` to append today's entry to `CHANGELOG.md` (or the user will run it). Keep each entry to a few bullet lines.
